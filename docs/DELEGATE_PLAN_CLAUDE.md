# Collie 方向方案：能证明自己干完活的本地人类代理

状态：提案 v2（独立于 DELEGATE_ARCHITECTURE.md，另起炉灶）
作者：Claude（Fable 5）
证据基础：2026-07-20-21 对 collie 代码库的 7 份子系统深读 + 4 份市场调研 + 3 份战略提案评审 + 3 份对抗性安全/可行性/事实核查审查
v2 修订：初稿的核心强制机制（"唯一的工具分发咽喉"）被安全审查证伪，已重写；工期与浏览器合流范围按可行性审查下调；确认令牌、注入围堵、凭据加密三处按安全审查改为诚实可执行的版本。修订点在正文用「v2 修正」标出。

读法：第 1-3 节是方向判断，第 4 节是与 Codex 方案的分歧，第 5 节是设计，第 6 节是路线图，第 8 节是放弃准则。

## 1. 一句话结论

**方向对，但"全能"必须重新定义。** collie 不应该做"什么都能干的代理"——那个产品在 2024-2026 已经死过很多次（Rabbit R1 留存 5%、Humane 退货超销量、Operator 订一张机票花 24 分钟、ChatGPT Agent 未破圈）。collie 应该做的是：

> **一个住在你自己的浏览器和机器里、每一类差事都有可执行验收标准、每一个不可逆动作都拿收据的本地代理。"全能"是一类一类差事攻下来的结果，不是第一天的卖点。**

这恰好是 collie 基因（执行验证、诚实测量、token 精简、本地优先）的直接延伸，而不是转行。

## 2. 为什么这个方向成立（证据，非愿景）

**需求真实存在，且付费：**
- Manus 靠不可靠的结果交付 8 个月做到 ~$100M ARR——用户缺的不是能力广度，是可靠性和控制感。
- OpenClaw（前 Clawdbot）3 个月 24.7 万 GitHub star，证明"个人消息驱动的代理"需求爆炸；随后 CVE-2026-25253、26% 技能带漏洞、面板裸奔泄露，证明**缺的那一层是确定性的权限控制**——至今没有任何开源项目把它做成头等公民。
- Anthropic 自己的遥测：Cowork 会话 >90% 是非编程工作。"把打磨过的 coding harness 指向普通人的活"正是 2026 年被验证的打法，collie 想做的就是同一步棋。

**失败模式高度收敛，而 collie 的解药正好对症：**
- 全行业头号信任杀手是**默默地干错了还说干完了**（Manus 伪造完成报告、Genspark 失败照扣积分、Devin 20 个任务只成 3 个且无法预测哪个会成）。没有任何大厂给委托任务附带机器可校验的验收断言——这就是 collie 验证门的用武之地。
- 复合错误是数学问题：20 步、每步 95% 可靠 → 整体 36%。所以可行域是"短链条 + 可验证 + 可中断等待"，不是长自主链。
- 提示注入被 OpenAI 公开承认"可能永远解决不了"。答案是围堵架构（第 5.5 节），不是分类器。

**大厂的结构性空档（不是暂时空档）：**
- Cowork 网页/移动端后台代理**拿不到本地文件和你登录态的浏览器**；Gemini Agent 在 EEA/英国/瑞士被禁；企业因注入风险封 Atlas。"住在你自己机器和浏览器里的持久代理"是本地优先方案独占的位置。
- 支付全行业收敛于"代理备好、人类按下"（OpenAI 从站内结账撤退、Walmart 实测站内转化差 3 倍）。不用发明新模式，跟着共识走。

**今天就能做成的差事类别（证据支持）：**
1. 盯梢-通知（价格/名额/回信/收件箱监控）——长等待 + 微小可验证动作；
2. 调研-决案（带引用的深度研究)——只读、容错高，是 Manus 独立测评里唯一稳定强项；
3. 表单-事务（申请/挂单/续期）——自家 auto-apply-ext 已在生产环境跑出 9,481 条真实结果。

**诚实的底数（v2 修正：补齐总数，纠正口径）**：auto-apply 的 `~/.auto-apply/audit/done.jsonl` 共 9,481 条：submitted 4,829 / needs_human 1,373 / qc_blocked 1,186 / no_form_detected 767 / error 508 / wrong_location 464 / 其余 354 条（no_submit_button 150、already_applied 76、spam_flagged 63、unclear 33、job_not_found 31、user_cancelled 1）。无接管直达 submitted 占 50.9%（其代码里 already_applied 也计成功，口径需在台账里明确声明）。这不是失败——这是全行业都没有的**真实垂直完成率基线**，也是台账制度的起点，且它由一个 4,900 行、只针对 5 个 ATS 平台、调过约 9.5k 次的专用引擎打出——迁移到新差事类别时这个数字不自动继承（见 §6 阶段 3）。

## 3. 定位一句话

**"The delegate that proves its work — in your own browser."**
对外：别的代理说"完成了"，collie 给你看证据。
对内：验证门从代码走向世界——修 bug 的 repro-assert 循环，泛化成每类差事的"验收器"。

## 4. 与 DELEGATE_ARCHITECTURE.md（Codex 方案）的分歧

那份文档的领域建模是认真的，但我认为它对独立开发者是错误的施工顺序，且把 collie 最锋利的刀（验证）排到了第三里程碑。明确分歧如下（v2 修正：删去对其检查点模型与成本控制的两处不实刻画）：

| 维度 | Codex 方案 | 本方案 |
|---|---|---|
| 施工顺序 | 先建控制平面（Mandate 编译器、任务 DAG 编排器、Action Gateway、17 张表事件溯源），"PR 4 之前不选垂直" | **结果先行**：先让一类差事端到端跑通，基建按需被差事"拽"出来 |
| 中心对象 | Mandate（授权书）——权限中心论 | **验收器（done-check）——验证中心论**，权限是差事契约的一个条款 |
| 数据层 | 17 张表 + 事件溯源 + 投影 | **4 张表**（jobs/steps/waits/receipts），append-only 设计借鉴 auto-apply `tracker/store.py` 的 628 行 stdlib 事件溯源实现；生产验证量（9,481 条）来自其前身 done.jsonl 管道 |
| 任务模型 | 带租约/依赖/并行 worker 的 DAG | **线性步骤 + 耐久等待**。Manus 数据：12 步以上必崩。可行域内用不到 DAG |
| 持久化粒度 | 步骤边界前后落检查点，用 legacy Harness worker adapter 包装现有 Harness（不重构其内部循环） | **同为步骤边界持久化**。分歧不在这里——在于 Codex 引入 worker 租约/DAG，本方案用"一步 = 一个子进程"更简单地达到同样效果 |
| 浏览器 | 众多 adapter 之一 | **主干轨道**。用户登录态的浏览器就是凭据库，这是 2026 年唯一成熟、$0、独立开发者可用的行动轨道（凭据托管边界见 §5.5，比初稿说的更保守） |
| 验证 | Milestone 3 的"postcondition verifiers" | **第 0 天的头等公民**："没有证据就不算完成"是产品本身 |
| 现实约束 | 有 delegation 级 cost/time budget，但未展开订阅 vs 计量的定价现实；未提 WSL2、EU AI Act、注入围堵 | 全部显式处理（§5.5/§5.6/§5.7） |

保留其正确共识（这些也是市场共识）：模型不给自己授权、凭据不进上下文、不可逆动作要人批、等待是持久状态不是活进程。

## 5. 设计

### 5.1 四个核心对象

**差事（Job）** = 目标 + 验收器 + 缰绳 + 预算。
状态机：`queued → running ⇄ waiting → needs_you → done(verified | accepted) / failed / cancelled`。
`needs_you` 是头等结果不是错误：Devin 尸检的结论是**不可预测性比失败率更杀信任**——"这网站要 MFA，我停了，已备好 X" 2 分钟出现，好过装忙一小时。auto-apply 的 1,373 条 needs_human 就是这个行为的生产原型。

**验收器（done-check）**：每类差事一个可执行的世界状态断言，产出证据。
- 表单提交 → 重读确认页 DOM / 收到确认邮件（auto-apply 已实现邮件确认桥）
- 挂单上架 → 登出态重新抓取该 URL 看到 listing
- 邮件发出 → IMAP 已发送文件夹出现 message-id
- 调研报告 → 引用链接逐条重新抓取核验
- 盯梢 → 通知本身携带观测快照
铁律：**没有证据，最多是 `done(accepted)`（人类手动放行），永远不能是 `done(verified)`。** 台账只认 verified。

**缰绳（Leash）**：每个差事一份 JSON，确定性代码强制执行。

```json
{
  "may": ["browser:read", "browser:act:site=craigslist.org", "files:write:~/collie-out"],
  "may_read_private": false,
  "irreversible": "confirm",
  "spend_max_usd": 0,
  "budget": {"tokens": 200000, "usd": 0.50, "wall_clock_h": 24},
  "expires": "2026-08-01"
}
```

三档：**看（自由）/ 做可逆（缰绳内自由）/ 不可逆（发送、提交、支付、删除——需确认令牌）**。可预授权且带边界（"7 天内可回复已有买家，价格不得低于 X"）——写在缰绳里，不写在提示词里，不依赖概率性记忆召回。

**v2 修正 · 强制点：不是一个咽喉，是四条分发路径全部封死。** 初稿假设 loop.py:545 的 `tool.run()` 是唯一分发点——安全审查证伪。真实情况是模型有四条逃逸通道，门必须同时覆盖：

1. **门下沉到 `Tool.run` / `ToolRegistry` 分发层**，而不是 loop.py 的调用点——这样 loop 和 `progtool.py:100` 的 execute_code RPC 服务器（同一个注册表）都自动继承同一道门。
2. **按参数判定不可逆性，不按工具名。** `bash` 和 `browser_eval` 是万能逃逸口：`bash{curl -X POST}`、`bash{git push}`、`browser_eval{fetch(url,{method:POST})}` 都能做不可逆的事却只是一个"工具"。所以：delegate 缰绳下的差事**默认不给 bash 联网**（无网络命名空间，除非缰绳授予 send/spend），bash 的写类动词（push/rm/curl-POST）默认拒；**`browser_eval` 直接从 delegate 工具集中移除**（任意 JS 不可门控，仅留开发模式旗标下）；`browser_type` 只要 `submit=true` 就要确认令牌。
3. **浏览器桥要真密钥。** `browserbridge.py` 的 CSRF 闸只是常量头 `X-Collie-Bridge: 1`，对本地进程零防护——模型自己的 bash 一条 curl 就能驱动登录态浏览器绕过一切。修法：给桥加每守护进程随机 token（照抄 `progtool.py` 已有的 `hmac.compare_digest` + 0600 文件模式），`/enqueue` 必须带；更好的是让 daemon 成为唯一入队者，桥命令也走同一道进程内的门。
4. **"0 越权"的诚实定义**：门可见动作里 0 越权，且明文声明 bash 被限制/browser_eval 被移除。不做"bash 命令语义分类器"——那正是本方案要避开的策略引擎重活，改用"无网络命名空间 + 动词白名单"这种确定性围栏。

**确认令牌（v2 修正：确认边界 = 步骤边界，由此天然可跨进程死亡存活）：** 不可逆动作**永不在提出它的那一步执行**。提出步把一个**完全物化的动作记录**（精确参数）写库并以 `needs_you` 退出；人类批准这条记录；一个 daemon 侧的**确定性执行器（无模型）**照记录逐字执行并写收据。好处：
- nonce 绑定的是**具体待执行 payload 的哈希**，不是一句英文摘要——解决初稿的语义/DOM 不绑定漏洞（人批"以 ¥450 发布"，实际点击却不带价格）。
- 浏览器场景：扩展在确认时**快照实际表单字段值、冻结字段**，执行时若 DOM 与快照不符则拒绝提交（防 TOCTOU/改价）。
- 子进程中途死掉不影响——动作记录和 nonce 在库里，重启后执行器照常放行。

### 5.2 管家进程 colliejobd（唯一的新守护进程）

借鉴代码库里已被证明的守护进程模式（embed_server.py：unix socket、flock 串行冷启动、空闲自杀、客户端自动拉起）——但**诚实地说，那个模式只覆盖最容易的 20%**：colliejobd 还要管子进程生命周期、调度唤醒、以及一条让 webapp/TUI 能观察运行中差事的流式事件路径。

- 持有 `~/.collie/jobs.db`（SQLite WAL，就 4 张表）
- 调度唤醒：定时器、IMAP 轮询（移植 auto-apply tracker 的 IMAP→分类→对账循环的**取信逻辑**；分类器要重写对接 collie provider 栈，因为原版是 shell 出 `claude` CLI + 求职专用提示词，不是直接移植）、页面变化探测、人类确认
- 执行一步 = spawn 一个 `collie run` 子进程（带缰绳文件 + 预算环境变量），步骤结束落库
- daemon 侧的确定性执行器负责放行后的不可逆动作（见 §5.1 确认边界）
- **崩溃恢复 = 步骤级**：死掉的步骤按幂等键重跑。语义幂等键按差事类别设计：申请 =（公司, 职位, 档案哈希），挂单 =（物品, 账号）——这同时修掉 auto-apply 已知的 30 天去重窗口 bug。

**v2 诚实条款 · 步骤级耐久买了什么、付了什么**：它确实绕开"循环中断点持久化"，但代价是每个子进程冷启动要重喂全部差事上下文（目标/缰绳/前序步摘要），且面对活页面要重新读 DOM 定位——这正是复合错误数学最咬人的地方。对策是把步骤切细到"一步一个原子 DOM 动作"，让模型进步吸收在颗粒度上（§8）。OAuth 路径下 token 成本可接受；计量 provider 下每差事预算上限兜底。

**WSL2 诚实条款**：VM 睡了定时器就停。语义定义为 **"catch-up-on-wake"（醒来对账）**而不是假装 24/7——daemon 启动即对账所有过期 waits（mem_import 的 systemd timer 已是同款 `Persistent=true` 模式）。真要 24/7，未来加一个只发通知、不持有任何凭据的 $5 VPS 哨兵，本地优先不破。

### 5.3 浏览器：主干轨道，但只抽取中性原语（v2 大幅收窄）

**初稿的"三栈合一/全部并入"是错的施工判断。** 可行性审查指出：auto-apply 的 content.js（4,059 行）+ workday.js（740）+ lib.js 是一套**页面触发、自驱动、批处理、经 background→server.py→`claude` CLI 决策**的引擎；collie 扩展是**反过来的架构**——305 行、由 harness 循环命令、往单个专用 tab 注入自包含函数。把前者并入后者不是移植，是控制流反转 ~4,900 行还活着的生产代码（同时它是所有者正在用的求职流水线）。这是头号工期杀手。

**v2 修正后的做法：**
- **只抽取 collie 桥现在缺的、与架构无关的原语**：`wait_for(selector/text/url)`（替换写死的 800ms sleep）、`scroll`、`screenshot`、通用文件上传（解除 `background.js:135` 的仅图片 MIME 限制——不能传简历 PDF 是硬伤）。ATS 填表引擎**原地不动**，作为独立生产系统继续跑。
- **多步向导（workday.js 那种）不整体并入**：多步 DOM 动作若压进一条 `/enqueue` 命令，门只看见一次工具调用却跑了含提交在内的多个不可逆动作——破坏"一个动作=一次可门控调用"的前提。正确做法是**多步编排留在 harness**（一条桥命令 = 一个原子 DOM 动作），或让扩展内状态机在任何不可逆步（提交/发布/发送）前停下交回控制、索要确认令牌。
- **凭据托管边界是整个浏览器 profile，不是单站点**（安全审查纠正）：扩展持 `chrome.debugger` + `<all_urls>`，`browser_eval` 一行 `document.cookie` 就能外泄。所以站点白名单必须在 **debugger-attach / navigate 层**强制（非白名单 tab 直接 fail-closed），不能只在 `browser_open` 的 URL 上做；且 `browser_eval` 从 delegate 工具集移除（见 §5.1）。
- Playwright 后端保留给公开无登录页面（VSCODE_BROWSER.md 的双后端路由准则不变）
- **回归 fixture**：从 collie-codex `data/sessions/20260720-095249` 里**只截取 marketplace 相关片段**（该会话是"重发一条 5080 显卡 listing + 新建并发布一条工艺品 listing"这类**挂单发布**，不是成交交易，也混了 reddit/测试等无关消息——初稿把它说成"交易"恰好犯了本文痛批的过度声称之罪，已纠正）。做成 mock 桥重放器（录制的 /poll 命令流 → 断言动作序列 + 参数），预算 2-3 天；填表引擎的 DOM 启发式仍由 auto-apply 自己的测试门覆盖。

### 5.4 记忆：轻量分型，不建八命名空间

只加两样：
1. **常备规则（standing rules）**：身份、红线、偏好——写进 CORE blocks（每回合保证加载的通道，见 `memory.py:5` docstring 与 `:85` 实现），因为**规矩不能依赖概率性 top-k 召回**；
2. **差事情节记忆**：收据自动喂入 mem_import 的蒸馏管道，带结构化来源标签。

另加一条安全规则：**写记忆本身是被缰绳管的动作**（2026 年已有靠投毒长期记忆做时移注入的真实攻击面）。其余照旧——检索引擎（BM25+dense+RRF+rerank）本来就是强项，不动。

**v2 关键修正 · 私密数据腿必须可静态判定。** 安全审查指出：`context.py` 的 `auto_prefetch`（默认开）会把召回的私密事实注入**每一个**提示，CORE 私密块永远加载——所以"这个差事是否持有私密数据"是召回引擎的涌现属性，无法从缰绳静态判定。修法见 §5.5。

### 5.5 注入围堵（lethal trifecta 拆解，v2 改为真正可执行）

前提：注入不可根治。结构性保证：**任何单个差事不得同时持有 ①不可信网页内容 ②私密数据 ③无确认的对外发送**。

**初稿只做到"含 web 阅读的差事强制 confirm on send"——安全审查指出这不够**：confirm 不消除 ①②，被注入的页面内容可以社工人类去批准一次夹带私密数据的外泄发送。v2 强制版本：
- 凡缰绳授予**不可信 web 读取**的差事，门**直接关掉该差事的 `auto_prefetch` 并抑制 CORE 私密块**（不只是 confirm on send）——让第 ② 条腿从源头不成立，这样三条腿真正静态可判定。
- `may_read_private` 作为**显式缰绳能力**（见 §5.1 的 JSON）——是否允许持私密数据由 JSON 决定，不由召回涌现决定。
- 人类确认视图必须显示**完整发送正文**，不是语义摘要——防止摘要遮蔽夹带的私密数据。

已有的不可信内容围栏、SSRF 防护、CSRF 桥闸（加真密钥后，见 §5.1）继续服役。MCP 侧加信任门：工具描述哈希钉死，变更即要求人类重批（GitHub MCP 注入、mcp-remote RCE 都是 2025-2026 真实案发）。

### 5.6 成本与模型（纠正一个流行错误）

DeepSeek/Qwen 是计费的（`catalog.py:52`：$0.27/M in，$1.10/M out），**"$0 边际"只在订阅 OAuth 路径成立**。所以：
- 盯梢类的高频探测不走 LLM：页面差异哈希 + 本地嵌入相似度先筛，变化了才唤醒模型（嵌入已经是本地 $0）
- 每差事预算上限进缰绳（现有 COLLIE_MAX_COST 机制从每次运行升到每个差事）
- 台账记每差事真实 $ 成本——collie 的 token 精简基因在"常驻代理"场景里恰好是核心竞争力：别人 $200/月配额制，collie 一单几美分且可审计

**v2 诚实条款 · 凭据加密不是万能药。** 初稿的"age + daemon 内存密钥"对本方案的威胁模型是剧场：daemon 空闲自杀 + 无人值守唤醒意味着冷重启必须**无人**恢复密钥，密钥或其解锁秘密只能落盘 → age 退化为对"偷盘"威胁的混淆；而真正要防的是被注入的 agent，它有 bash 能读 age 身份文件或直接调用已解密 token 的 MCP 工具；且 WSL2 下文件在 Windows profile 里，Windows 侧恶意软件本就够得着。诚实边界：**无人值守唤醒时，静态加密无法门控 agent**——所以有价值的发送/不可逆凭据一律走人类确认门（不做无人值守的有价值发送），只读监控凭据最小权限。要真的做静态防护，用 OS keyring/TPM 交互式解锁，并接受"无人值守差事就用不了这些凭据"。

### 5.7 合规小事但现在做

EU AI Act 第 50 条 2026-08-02 生效：凡代表用户对第三方发消息/邮件/表单，加可配置的 AI 披露行。auto-apply 场景同样适用。成本半天，躲掉一类未来麻烦。

## 6. 路线图（自用成军 → 数字说话 → 才谈开源）

评审团三票全票：**所有者本人是第一用户**，在自己的真实生活差事上跑出数字之前，不做产品化。**v2 修正：工期按可行性审查上调，阶段 0 拆分，阶段 3 数字降级为待校准假设。**每阶段维护 `tests/run_all.sh` 的 111 项核心测试全绿（改 loop.py/注册表期间冻结 harness 新功能轮次）。

**阶段 0 · 缰绳与收据（v2：拆成 0a/0b，合计 3-4 周）**
- **0a（1-2 周）**：门下沉到 `Tool.run`/注册表层（覆盖 loop + progtool RPC）；浏览器桥加真密钥；bash 无网络命名空间 + 动词白名单；`browser_eval` 移出 delegate 集；工具不可逆性按参数判定；收据落库；**文件/CLI 式确认**（被门动作写 pending-confirm 记录并以 needs_you 退出，`collie confirm <nonce>` 在下一次运行放行）——因为 harness 里现在**零**中途人类输入基建（webapp 在 HTTP handler 里同步阻塞，唯一输入点是 tui.py:439 的运行间提示）。
- **0b（1-2 周）**：daemon 侧确定性执行器 + 确认边界=步骤边界（§5.1）。交互式 TUI/Web 中途确认 UI 推到阶段 1（daemon 给它天然的家）；手机通知推到阶段 3+。
- 退出条件：**连续 20 个真实差事动作，门可见动作 0 越权、0 重复副作用**；一次完整的"拦截→CLI 批准→执行器放行→收据"闭环。

**阶段 1 · 管家与盯梢类（v2：6-8 周，非 1 个月）**
colliejobd（子进程生命周期 + 调度 + 流式事件路径，不止 embed_server 的 20%）+ 4 张表 + 定时/IMAP 唤醒（移植取信逻辑，分类器重写对接 collie provider）+ catch-up-on-wake。**先 CLI-only 观察**（`collie jobs`/TUI 看运行中差事），webapp 保持同步 run 不动——webapp→daemon 的流式重构本身改了 SSE 架构，单独排期，不塞进本阶段。
退出条件：一个盯梢差事**跨 WSL 重启存活**、无人值守跑满一周、通知携带证据快照。

**阶段 2 · 浏览器原语与事务类（第 2.5-4 个月）**
桥原语补齐（§5.3 中性原语清单，非三栈合一）；站点白名单在 debugger 层强制；市场挂单重放 fixture（mock 桥）；申请/挂单两个事务差事**原生建在 collie 桥上**，配语义幂等键。
退出条件：一笔完整事务（真实挂单或真实申请）在缰绳下完成，**≤1 次人类确认**，收据 verified；重放 fixture 全绿。

**阶段 3 · 三类差事日用与公开台账（第 4-6 个月）**
盯梢/调研/事务三类进入每日自用；周度台账自动生成：差事数、verified-done 率、needs_you 率、越权数（必须为 0）、重复数（必须为 0）、$ 成本、估算省时。**台账只认证据确认的完成**——结构上杜绝 Manus 式自报完成。
**v2 修正 · 退出数字是待校准假设不是既定目标**：初稿的 盯梢≥95%/调研≥80%/事务≥60% 中，只有事务的 51% 有基线（且来自 4,900 行专用引擎），盯梢/调研零历史无基线。改为：阶段 1/2 每类真实用 2 周后，把阶段 3 门槛设为 **实测基线 + 明示增量**；事务拆成 "ATS（基线 51%）" 与 "新事务类型（无基线，先探底）"，使 §8 的冻结触发器不挂在从未推导过的数字上。

**阶段 4 · 开源与生态（第 6-12 个月，条件触发）**
仅当阶段 3 校准后数字达标：以 "the delegate that proves its work" 开源（Apache-2.0 内核——echomem 是收费 SaaS，这个组合是 2026 市场接受的模式）；errand-bench 按 collie-bench 的 SHA 钉死格式公开每类差事完成率/成本；缰绳 JSON 字段向 AP2/Verifiable Intent 对齐（已捐 FIDO，抄字段成本低，等轨道对小玩家开放时即插即用）；collie.run 补上委托叙事。
时机注：OpenClaw 创始人 2026-02 去了 OpenAI、项目移交基金会，"小而可审计的本地代理"有 6-12 个月窗口。

## 7. 不做清单

- ❌ 云协调器/多设备同步（阶段 4 之前）；哨兵 VPS 只发通知、零凭据
- ❌ 自动支付、任何支付轨道集成（Visa/Mastercard 皆为合作方管制的 pilot，独立开发者上不去；跟随"代理备好、人类按下"共识）
- ❌ `browser_eval` 进入 delegate 工具集（任意 JS 不可门控，仅开发模式）
- ❌ delegate 缰绳下给 bash 联网默认权限（无网络命名空间 + 动词白名单）
- ❌ 把 auto-apply 的 4,900 行 ATS 引擎整体并入 collie 扩展（控制流反转，原地保留）
- ❌ 技能市场（OpenClaw 的供应链事故：恶意技能冲到榜一）——只做小型签名钉版能力表
- ❌ 并行多智能体 DAG/swarm（可行域内用不到，复杂度先杀死你）
- ❌ 聊天产品化 UI 重写（composer 加一个差事卡片视图即可起步）
- ❌ 再造编排框架/记忆层/浏览器执行器（三个赛道全部拥挤且被 VC 灌满——组合，别再造）
- ❌ "什么都能干"的营销（尸体名单见第 2 节）
- ❌ 放弃 coding harness——它是信誉抵押品（78% SWE-bench@110k tokens 的诚实测量方法论就是台账模板，但该数字 collie 自己的文档也标注为"方向性、未证明"），冻结新功能轮次，只保回归

## 8. 风险与放弃准则

| 风险 | 对策 / 触发即执行 |
|---|---|
| 模型能力不够，事务类完成率上不去 | METR 时间地平线 ~4-7 个月翻倍：任务颗粒度吸收模型进步（今天切细步骤，模型变强步骤变粗），架子不重写。**若阶段 3 校准后 verified-done 整体 <50%，冻结 delegate 线，回归 coding harness 等一个翻倍周期** |
| 自己都不用（最诚实的信号） | **连续 2 周自用差事数为 0 → 方向证伪，停止投入** |
| 浏览器出一次未授权动作 | 立即吊销全部对外发送权限，根因未修复不恢复；台账公开记录 |
| 缰绳被逃逸通道绕过（progtool RPC / bash curl 桥 / eval） | §5.1 四路封死是阶段 0a 的**前置条件**，不是后续加固；未封死不进阶段 1 |
| 凭据安全 | 无人值守只用最小权限只读凭据；有价值发送一律走人类确认门；MCP token 文件权限收紧，但不宣称静态加密是安全升级（§5.6） |
| 独立开发者精力 | 每阶段单主题；任何阶段超期 50% 即砍范围而不是加班（此规则已**预先应用**于阶段 1 的重新排期） |
| 大厂突然开放本地+浏览器代理 | 差异化底线是"证据收据 + 用户自己的登录态 + 可审计缰绳"——大厂云端架构给不了；若真给了，errand-bench 与台账方法论仍是可迁移资产 |

## 9. 一页总结

collie 已经有了别人没有的三样东西：**跑通过真实挂单发布的自有浏览器桥、9,481 条真实委托结果的垂直基线、把"验证"刻进骨头的 harness**。缺的四样东西——缰绳、管家、验收器、收据——每一样都有代码库内的种子（工具注册表分发层、embed daemon 模式、auto-apply QC 门与邮件桥、checkpoint/undo）。

安全审查把初稿最锋利的卖点（确定性缰绳）先证伪再修复：真正的强制点不是一个咽喉，是注册表分发层 + 桥真密钥 + bash 断网 + eval 移除四路封死，且不可逆动作在步骤边界由无模型执行器放行。这道修订本身就是本方案的立身之本——**别的方案把安全当营销，collie 把自己的安全声称拿去对抗性证伪，改到能兑现为止。**

先让它给自己干活，用台账证明，再让它给别人干活。
**别的代理说"做完了"；collie 给你收据。**
