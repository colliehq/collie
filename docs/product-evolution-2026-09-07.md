# Collie 0.25：任务连续性与交付复审

本轮基线为 `34084d0e`，开发分支为 `feat/product-evolution-2026-09-07`，最终功能提交为 `561298a5`。用户授权继续检查、修改、本地提交，并使用 Claude Code 订阅做真实实验；默认选择仍是“跳过可选步骤，必要时才询问”。本轮于当地 9 月 6 日晚开始，文档日期采用 UTC。

## 产品判断

Collie 已有可工作的原生循环、Claude Code worker、持久任务、队列、恢复和验证能力，但用户仍需要自己记住几件事：当前对话在哪个项目里、上次怎样要求检查、停止后还有什么没执行，以及隔离成果到底存在哪里。这些信息一旦跨页面或跨进程丢失，功能再多也会显得不可靠。

0.25 把这些信息放回同一个任务。常规操作仍直接继续；可选工作省略后保留说明；需要核对的未知副作用继续保留恢复边界。没有增加固定对话次数限制，也没有把“少打扰”实现成放弃用户要求的必做工作。

本轮没有替换 JSON 执行日志，也没有重写整个前端框架。执行记录、执行者租约和界面状态之间的断层已有可复现证据，先修这些边界，比迁移框架更直接影响使用体验。

## 已实现的变化

| 使用中的问题 | 0.25 的行为 |
|---|---|
| 刷新后忘记 Required 和手工检查命令 | 桌面 Web 按对话保存本标签页的运行选择，可明确恢复自动选择；不保存 Pack 自动应用权限 |
| 对话的项目与检查发现使用不同目录 | 检查发现跟随保存的会话目录；新任务可明确选择文件夹，错误路径在执行前拒绝 |
| 切换对话时文字或图片串到其他任务 | 草稿归属于对话；本页导航保留附件，刷新后提示重新附加或明确只保留文字 |
| 排队保存的回执晚到，草稿仍显示为未发送 | 回执按原对话及草稿修订清理；离开再返回也不会留下已确认请求的重复草稿 |
| Stop 后保存的要求只在原页面可见 | 今天、侧栏和需要你显示等待中的请求；继续需要明确点击 Send next |
| 后台任务无法推进，却没有可见原因 | 有活动任务时显示 Mission 调度器错误及运行状态 |
| 隔离任务后续又创建新分支，难找之前的修改 | 首次执行保存 worktree 元数据，后续复用同一个目录 |
| 隔离成果在系统临时目录中容易遗失 | 新工作区保存在会话存储旁的 `workspaces` 目录；旧路径保留兼容，不自动搬迁 |
| 分支提示使用 `git diff main..branch`，看不到未提交成果 | 页面显示实际目录，并提供“将修改应用到主项目”；补丁包含未提交、新增及二进制文件 |
| 补丁通过文本管道，二进制或 CRLF 差异应用失败 | Git 补丁全程使用原始字节，独立检查后应用 |
| 应用时会话可能同时执行，或应用成功但记录未保存 | 使用与执行器相同的会话租约；写入副作用边界后应用，最终记录成功后才清除边界 |
| Git 耗时操作长期锁住整个会话文件 | Git 执行期间保留执行租约，但释放日志文件锁；读取与改标题可以继续 |
| 保存工作区失败，内存里留下“仍在执行”的任务 | 拒绝启动 worker，明确结束运行记录、释放租约并报告失败 |
| 已确认补丁应用成功，恢复后仍困在旧目录 | 确认“已完成”时同步更新工作目录，不再重复应用补丁 |
| 目录丢失后网页只能提示使用 CLI 的 `--cwd` | 提供明确的目录恢复入口；只变更后续工作位置，不冒充找回文件 |
| 应用回主项目后，外部 worker 仍尝试恢复旧目录会话 | 目录改变时创建新的 worker 会话并带入近期文字回顾；后续同目录交流继续复用新会话 |
| 桌面快捷命令绕过执行锁、对话历史缺少归属 | 效果发生前取得会话租约，记录同一会话；未知结果保留边界，页面显示记录失败的说明 |
| 清理 worktree 时可能删除父目录中的其他内容 | 先确认是已注册且非主项目的 worktree；只清理空的分配目录，保留邻居文件 |
| 恢复页与执行器使用不同的会话目录及锁 | 统一存储根目录解析，兼容属于所选安装的显式旧式目录，拒绝套用其他安装的覆盖设置 |
| 历史列表、分支导航、恢复扫描反复解码长日志 | 使用可重建的 SQLite 元数据索引；执行与实际恢复仍读取原始日志 |
| 已经跳过取名，下次打开浏览器又被询问 | 可选取名的跳过偏好跨浏览器重启保留 |
| 新任务后台刷新检查命令，快速发送被无声拦住 | 未改变的工作目录不因后台发现刷新而临时失效；用户主动换目录仍先检查 |
| Pack 展开后运行设置遮住发送按钮 | 去掉改变固定定位参照的输入区模糊效果，设置面板保持在输入区上方 |

这些边界各有明确职责：

| 内容 | 保存位置与决定权 |
|---|---|
| 会话历史、当前目录、未知操作 | JSON 会话日志；执行与恢复直接读取 |
| 当前执行者 | 与同一会话目录绑定的系统文件锁及执行租约 |
| 已确认的后续请求 | 持久 task inbox；以保存回执和执行边界区分“已保存”与“已读取” |
| 草稿、尚未发送的运行偏好 | 当前浏览器标签页；不会自动成为执行授权 |
| 历史列表和分支导航 | 可丢弃的 SQLite 索引；不是执行权限或恢复结论的来源 |

## Claude Code 真实实验

使用本机 Claude Code 2.1.221，模型为 `claude-opus-5`。实验通过实际 Collie Web UI 启动，分别使用外部 `claude-code` worker 与 Collie 原生循环。订阅进程清除了可能切换到 API 计费的环境变量；输出中的美元统计若出现，是工具报告的 API 等价成本，不代表实际订阅账单。

每个任务包含初次实现、刷新后追加兼容需求、同会话无工具追问及手机宽度检查。每轮指定 `python -m unittest -q` 为 Required 检查，并在工作区外执行独立验收断言。任务明确声明一个无账号的云端风格指南为可选，观察是否可以省略而继续。

| 场景 | worker | 两轮独立断言 | 同会话追问 | 总耗时 |
|---|---|---:|---|---:|
| 区间合并，追加 `merge_touching` 参数 | Claude Code | 106 + 207 通过 | 通过 | 165.8 秒 |
| 区间合并，追加 `merge_touching` 参数 | Collie | 106 + 207 通过 | 通过 | 147.3 秒 |
| 深层配置合并，追加 `delete_none` 参数 | Claude Code | 7 + 12 通过 | 通过 | 158.6 秒 |
| 深层配置合并，追加 `delete_none` 参数 | Collie | 7 + 12 通过 | 通过 | 163.7 秒 |

四组共 664 项独立断言通过。八个编码阶段均保留 Required，宿主实际执行检查且退出码为 0；刷新后的第二轮没有退回 Auto。四组均无浏览器脚本错误，390 px 视口无横向溢出。耗时只是本次样本，不能当作 worker 的普遍速度排名。

另做了两组隔离交付实验：

- Claude Code 的区间任务两轮 313 项断言通过，但首次应用包含 Python 字节码的二进制补丁时失败。相同原始补丁的字节模式 `git apply --check` 通过，证明问题在补丁运输。修复后从原会话在网页重新应用成功，主项目再次通过 207 项断言，原隔离目录保留；失败日志没有覆盖。
- Collie 的配置任务在新持久工作区完成两轮，刷新后仍使用同一路径，主项目在应用前保持原样。随后经网页应用成功，主项目通过 12 项断言，隔离目录保留；完整流程 215.0 秒。

应用完成后又在原 Claude Code 对话中发出一次真实修改要求：创建 `continuation.txt`。新 worker 会话在主项目正确写入指定内容，宿主检查通过，旧隔离目录没有该文件；本次续聊 7.1 秒。这个实验专门验证交付之后还能继续工作，而不只验证 Apply 按钮返回成功。

这些是小型标准库项目的受控端到端实验，不是 SWE-bench，也不能证明大型仓库或所有连接器任务的成功率。

## 历史导航性能

固定样本为 80 段会话、每段 200 次用户交流、约 800 条消息，总日志 91,801,342 字节。每次读取最近 80 段会话；先执行一次，再取六次重复读取的中位数。

| 指标 | 原实现 | 0.25 |
|---|---:|---:|
| 重复读取中位数 | 171.986 ms | 22.245 ms |
| 每次重复读取解码的完整日志 | 80 | 0 |
| 最终实现首次建索引读取 | — | 231.605 ms |

该样本重复导航约快 7.7 倍。缓存使用文件身份、大小及纳秒修改/变更时间识别源文件变化；删除再创建、同尺寸替换、跨进程读取、缓存损坏或不可用均有测试。缓存不可用时回退到原日志，不阻止会话使用。恢复列表只跳过确认未变且无活动状态的历史；真正的恢复决定始终读取日志。

这没有消除每次 checkpoint 重写完整 JSON 的成本。没有足够理由在本轮引入一套新的事件日志格式，同时承担中断恢复迁移风险。

## UI / UX 复验

实际加载了今天、任务、新任务、设置、应用、实时协作、设备、活动，以及必要依赖与恢复面板。桌面 1380×960 与手机宽度 390×844 的截图和浏览器错误记录保存在实验目录。检查涵盖入口可见性、工作目录提示、弹层、页面溢出和主要控制；自动检查没有浏览器脚本错误或横向溢出。

工作目录默认折叠，只显示实际位置，需要时展开选择、应用或恢复。中文简体与繁体覆盖新增控件；手机布局隐藏桌面键盘快捷键提示，给内容和输入框留出空间。队列和调度问题采用页面内提示，不自动弹出额外确认。

当前界面仍有多种高级执行方式；运行设置依然是高级功能面板。0.25 优先减少重复配置和丢失上下文，并未证明首次使用者能无需引导理解全部模式。

## 审阅结果如何处理

Claude Code 完成四轮独立源码审阅，覆盖产品路径、存储与恢复、任务连续性及最后的边界修复。审阅建议逐项核对，不直接当作事实。

- 复现并修复了恢复根目录、快速命令租约、全局等待请求、工作区交付、补丁字节运输、迟到回执、注册状态残留和长时间文件锁等问题。
- “Windows 所有文本补丁都不能应用”的表述过强：简单文本测试通过；真实二进制补丁失败，原始字节检查通过。修复和结论以实际样本为准。
- 没有采用“隔离目录丢失时，把 Apply 自动改成绑定主项目”的建议。那会把没有复制成果的动作显示成应用成功。新入口明确说明只更改目录。
- 没有把已保存的隔离目录视为只读 Plan/Review/Test 的禁区。`Current` 表示这段对话当前所在的目录；只读审阅应能检查刚完成的隔离成果，显式应用才返回主项目。
- “损坏日志会被当成空对话继续执行”没有复现：执行前已有恢复检查，损坏日志会被拒绝。没有放宽未知记录状态的验证。

仍需清楚保留的范围：

- 未实际操作手机设备、麦克风、摄像头、付款、邮件发送或真实第三方账号；视口检查不等于全部设备认证。
- 草稿和运行设置在当前标签页的 sessionStorage 中保留，不是跨设备同步；附件只有服务端确认保存后才具备持久队列语义。
- 更换工作目录会重新建立外部 worker 会话，传入近期文字回顾；不会声称迁移了 worker 的全部内部上下文。
- 原始 JSON checkpoint 的写入量仍随历史增长；索引只改善导航与扫描。
- 主项目存在未提交改动时，应用隔离成果仍要求先处理该状态；可以保留成果并继续其他工作，不强制暂停整项任务。
- 旧临时 worktree 不会自动迁移。已经被外部删除的未提交文件无法靠会话历史复原。
