## 第一批执行连续性修复

- 普通 Harness 默认轮数上限从 50 改为 0，与交互选项一致。显式用户上限仍生效。
  脚本模型完成 65 次工具调用后正常回答，共 66 轮，没有第 40/50 轮中止。
- 对实际内置只读工具记录可安全恢复的执行边界。恢复时补齐缺失的工具结果，说明
  哪项读取中断、哪些排队工具没有执行；不自动重放工具，不改写原始磁盘会话。
  外部操作、脚本和未经主程序确认的只读声明仍保留副作用核对边界。
- delegate 改为主任务创建的只读调查：沿用当前模型和连接，继承取消和共享预算，
  不再修改全局环境或重新选择账户。子任务不能写文件、执行命令或继续分派；
  需要这些操作时由主任务完成。子任务同时看到原始用户要求与主 agent 提议的分工。
- 子任务记录 parent_run_id，费用计入父任务，汇总只计入父任务以免重复统计。
- 运行记录区分正常完成、取消、轮数上限、预算上限、输出截断和错误。
  `success` 表示执行正常结束；`verified` 单独表示实际验证证据，评测器仍可覆盖 success 为任务评分。
- Auto 验证不再因 auth/fix/test 等主题关键词变成 Required。升级复杂度只读取运行回执；
  “错误已修复”的普通文字和“没有运行检查”不会伪造失败。
- 自动 Git 撤销快照使用内部提交身份，不要求先配置 Git 用户姓名和邮箱，不修改 Git 配置。
  无身份的新环境下，脏文件、未跟踪文件、HEAD 和暂存区的完整性测试通过。

## 源码审查中纠正的推断

- 无工具调用的 assistant 回答作为结束条件，也是多个开源循环的常见机制。
  仅凭这个分支不能证明 Collie 经常过早结束，不增加容易误伤正常回答的关键词循环。
- Web 的 Allow for this run 只承诺本次运行，结束后规则消失符合界面文字。
  跨轮持久授权的入口和体验需要单独验证。
- `force_edit` 的工具收缩默认仅用于明确启用该选项的评测路径，不能描述成
  每个普通用户都会遇到的第 40 轮停止原因。

## 长上下文与再次恢复

新增保留完整原始会话的上下文压缩：模型使用“摘要、用户要求、近期完整工具组”的
投影，磁盘会话保留全部消息。摘要作为低优先级历史交接，不能覆盖系统约束；当前用户
要求保留原文，最近的图片请求跨越切点时保留原始图片。压缩切点不能拆散工具调用和
结果。摘要调用计入实际调用次数及共享预算，支持取消；失败或损坏的检查点回退到原历史。

真实 Claude 长中文任务在受控的较低阈值下触发压缩，估算输入从 22,867 降到 10,823
tokens，40.18 秒完成，磁盘 80 条消息完整保留。最终回答遵守两条中文输出约束，并保留
位于长请求中间的验收编号 `LEDGER-LONG-061`。随后启动新进程恢复，4.2 秒、一次模型
调用正确返回该编号，没有重新生成摘要。相关整合检查 210 通过、1 跳过。

这不代表摘要可无损代替所有历史：较早图片的视觉细节仍依赖历史描述，旧用户要求同时
依赖摘要和有界原文摘录。超长摘要、无法保全当前要求的切分或没有明显收益的重复压缩
不会被采用。当前默认阈值为估算 48,000 tokens，可在设置中调整。

## 停止和结束状态

普通消息现在直接进入统一运行流程，不再先额外调用模型分类。真实浏览器复杂审查请求
的停止按钮在约 25 毫秒内可见，取消在约 1.9 秒确认，无页面脚本错误；这是单次本机
实测，不是延迟保证。停止和错误保留已生成的文字及工具进度，不再删除整条回答。
排队后续消息只在正常完成后自动启动，取消、错误或上限不会自动触发下一项。

修复了结束保存清除未知操作边界的缺陷。中断中的内置只读操作可以恢复；可能已产生
副作用的操作保留核对记录，CLI/Web/REPL/TUI 均不能因为保存了部分回答就把它变成
可重放。工具批次中已完成、执行中、未开始的调用分别保留真实结果、未知结果和未执行
说明。Ctrl-C 返回带部分进度的取消结果，同进程后续对话会检查恢复状态。

取消或失败后不再启动新的宿主验证命令；“未运行”证据不会显示成“检查失败”。

通过；新文案的繁简体覆盖检查发现缺漏，已补齐。正在继续验证命令执行中的取消，及
跨页面、跨进程的补充消息持久化。

## 命令执行中的取消

`c651c96b` 主分支完整回归为 2562 通过、10 跳过，耗时 367 秒。此结果不包含随后
独立工作区中的命令取消改动。

Bash、Grep 在等待命令时检查取消信号，Windows 先给受信任的启动器建立 Job 归属，
再释放实际命令；使用实际 Python 解释器避免虚拟环境启动器抢先派生进程。普通结束时
保留明确后台启动的服务，取消、超时、异常时终止所拥有的进程。未确认终止或后台交接
失败通过宿主字段写入恢复记录，不能只依靠模型读到一条警告。

`execute_code` 同样支持执行中取消，复用通用进程归属实现。外层脚本结束后给正在退出
的内部工具一个有界收尾时间，保留其部分输出；仍在执行的内部操作继续保留恢复边界。

真实浏览器运行“execute_code → bash → Python → 延迟写文件子进程”，最初出现外层
停止而内层继续运行的失败。排查发现 Windows 的系统 Python 应用别名通过安装管理器
启动进程，普通命令 Job 未覆盖实际解释器。现在仅在默认 `python` 解析到这种别名时
优先使用 Collie 当前的实际解释器，已选定的虚拟环境及真实 Python 路径保持优先。
同一场景修复后约 0.25 秒确认取消，延迟文件和正常完成标记均未出现，无遗留恢复阻塞；
用户可直接在原会话继续询问，Claude 正确回答前一个命令被中断。

进程归属仍不是操作系统沙箱：显式调用系统服务代为启动程序、POSIX 主动脱离进程组等
路径不能笼统算作已被 Job 或进程组覆盖。实际工具结果和恢复边界必须据此解释，不能
把“已终止所拥有的进程”推广为“外部世界没有任何变化”。

## 后续整合与实际交付

下列记录补齐前面按时间写下的阶段状态，描述最终整合后的行为。

### 持久输入、图片与设置

会话执行使用操作系统锁；输入账本先保存后确认，保留请求身份、内容、设置和附件引用。Web 默认排队、显式插话分开处理；CLI、REPL 和 TUI 可以查看待处理请求并手动开始下一条。停止或失败不会自动放行下一项。外部 worker 的首次请求也在传输前写入会话，避免刷新后只有空白进度或中断后缺失原始要求。

图片和 IDE 上下文不再只依赖临时上传缓存。真实实验先接受带图请求、重启本地服务器，再用同一个请求 ID 重试，确认只保存一次；模型正确回答图片计数、颜色和精确上下文标记，随后也能区分历史图片与新图片。一次直接 SDK 实验使用 `opus` 别名触发冻结模型身份不匹配，未计为成功；使用该实验实际返回的规范模型 ID 后通过。

预算、生成参数、路由及四项敏感能力在接收时冻结。运行开始后不因另一个页面修改设置而改变已接受的条件；摘要、重试、子任务和 Pack 候选仍纳入共享预算。冻结过程本身也经过并发检查：最初两项回归复现读取多版设置、读到部分应用的环境；改为同一版设置快照和互斥应用后，相关 99 项检查通过。没有声称消除了 Live 等旧模块的全部全局设置读取。

### Mission 完整目标与中途变更

原始真实代码 Mission 样本耗时 97.8 秒，未修改文件，却出现声称完成代码修改的输出。该失败记录保留在 `mission-real.json`。专用代码 Mission 现直接调度原生代码执行器，检查绑定实际修改和当前工作树，而不是把旧测试通过当作目标完成。

修复后 `mission-v2-real.json` 记录 168.42 秒、44 个模型迭代；项目 57 项测试通过。宿主另用原始行为作参照运行 36 个 CLI 参数组合，验证类别筛选与原有 since/total/json 组合兼容。这里的 44 轮是自然完成；默认 `0` 表示不设固定轮数上限，显式资源和时间限制仍有效。

需求保存在精确账本中，状态里的有限长度摘要只用于展示。Web 新增独立 Mission 页面、可跨刷新保留的草稿、运行中补充和完整需求历史。唯一请求 ID 支持安全重试；新要求应用后，旧的完成证据被标记为过时，完成事务还会检查晚到输入。

`mission-notes-real.json` 完整走过“暂停时保存说明 → 刷新 → 恢复 → 运行中追加 Unicode casefold 需求 → 完成”。耗时 120.183 秒，两条原文完整保留并应用，6 项独立验收通过。复核另外修正了重试后未释放 SQLite 事务的分支，以及运行中错误禁用补充按钮的问题。桌面与 390px 手机页面均检查，无 JS 错误或水平溢出。

### Pack 保存与应用

Pack 选中结果先保存为可验证的差异，再清理候选目录；默认不立即应用时仍可日后查看。新增 Web 查看、刷新、应用和 CLI `--saved` 入口，查看及应用不调用模型。应用检查基线、路径和内容，遇到冲突保留当前修改，不以覆盖文件来掩盖差异。
