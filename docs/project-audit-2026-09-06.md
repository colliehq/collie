## 项目结构判断

| 层次 | 主要代码 | 判断 |
|---|---|---|
| 用户入口 | `cli.py`、`webapp.py`、Web UI、浏览器扩展、原生桌面 | 入口丰富，应共享权限与参数验证规则，减少不同入口的行为差异。 |
| 执行与验证 | `loop.py`、`mission.py`、`missionweb.py`、runner adapters、verification | 已有大量确定性测试；保留“执行证据决定完成”的核心设计。 |
| 持久化与恢复 | Missions、jobs、control plane、Live store | 持久化不仅需要原子写入，也需要容量控制和跨进程事务语义。 |
| Live 感知与交互 | `live_copilot.py`、`sensevoice.py`、`live_voice_relay.py` | 新功能集中处，最需要防止后台结果越过会话和权限边界。 |

当前工作树约有 153 个顶层 Python 模块、9.9 万行 Python 源码。
`webapp.py` 超过 5,500 行，`mission.py` 超过 5,300 行，`cli.py` 超过 4,800 行。
后续应按业务边界逐步拆分，并以跨入口行为测试保护迁移。

## 已修复的问题

| 优先级 | 可复现问题 | 修复后行为 |
|---|---|---|
| P1 | `update_permissions(listen="false")` 会开启监听，且绕过使用 `is True` 的同意检查。其他权限也接受字符串、整数等非布尔值。 | Store 入口和持久化读取严格校验布尔类型；HTTP 和模型工具的启动入口保留原始值交给 Store 校验；无效请求不修改状态。 |
| P1 | 转写完成后先检查 session，再在另一段锁内追加事件；两段之间新建会话时，旧转写可写进新会话。 | 追加每条转写时传入原始 `session_id`，在实际写入锁内再次校验归属；旧结果被拒绝，临时音频仍被删除。 |
| P1 | 关闭语音对话后，进行中的模型请求仍可追加回答；停止会话未清理 dialogue 的进行中标记。 | 回写前重新检查 `voice_dialogue`；关闭后丢弃回答并释放标记；停止时清理两条分析通道的进行中标记及领取时间。 |
| P1 | 事件数量上限不能保证 UTF-8 文件大小。1,200 条每条 4,000 个中文字符的合法事件可写出约 14.5 MB 的文件，超过自己的 4 MiB 读取上限。 | 序列化后按实际字节数检查，分批裁剪最旧事件并保留最新事件；其他内容仍超限时，拒绝写入并保留上一份可读状态。 |
| P2 | SenseVoice 启动 ffmpeg 没有传入 Windows 隐藏控制台参数，后台语音处理可能闪出命令窗口。 | 使用现有 `plat.no_window_kwargs()`；跨平台窗口检查通过。 |
| P1 | 语音 relay 播报完成后无条件恢复监听，可能覆盖用户在播报期间手动关闭监听的选择。 | 临时暂停领取单次恢复凭据；显式监听设置使凭据失效，停止或切换会话也不能恢复；不再由 relay 代填同意参数。 |

## 已完善的功能：结束会话后的回顾与导出

原先停止 Live 后，页面隐藏摘要、提醒和后台任务区，用户难以整理本次协作结果。
现在停止后仍保留回顾，刷新后也可继续查看，已结束会话的实时操作按钮禁用。

- 新增 **Markdown 导出**，包含起始上下文、AI 摘要、笔记、未隐藏建议和后台任务最后记录状态。
- 上下文日志默认不导出，勾选后导出全部保留事件；音频、截图和 Avatar 连接凭据不进入文件。
- 支持中英文，导出不再调用模型；下载接口要求认证并核对会话编号，旧页面不能下载后来新建的会话。
- 明确提示只保留最近一次会话，应在新建前导出；导出不是完整录音记录，任务记录也不是最新执行结果。
- 新增独立导出模块，避免继续把文本格式处理堆入 `webapp.py`。

使用方式见 [Live 文档](interviews.md#review-and-export)。

## 后续优先事项

以下来自源码检查，本轮没有进行相关架构改造或声称完成故障复现。

从用户功能完整性看，建议按以下顺序继续：

1. **语音准备与故障恢复。** 在 Live 内集中显示模型、ffmpeg、播放组件和麦克风状态，
   给出测试录音、测试播报、重试入口；补充录音序号与会话归属检查，并配合有界处理队列。
   目前神经语音和 SAPI 的音频播放都依赖 ffplay，缺少它时仍需完善回退或明确错误提示。
2. **任务结果回流。** Live 会话中的 Mission 显示最后记录状态；应订阅任务完成或失败事件，
   提供查看执行证据、失败重试和把结果带回笔记的入口。
3. **可选会话历史。** 当前已支持主动导出；下一步可让用户自行选择保留历史、关联项目和
   删除记录，避免把所有实时上下文默认长期保存。
4. **Avatar 外部服务生命周期。** 补足远程启动中切换会话、自动到期或语音停止时的清理与重试；
   在真实提供方验证连接、嵌入与断线恢复后，再视为完整外部服务功能。

工程层面仍需：

1. **Live 状态的跨进程一致性（P1）。** 当前 `_LOCK` 是进程内 `RLock`，多个进程仍可同时
   对同一个 JSON 文件执行读—改—写；原子替换只能避免半份文件，不能防止覆盖另一进程的更新。
   建议选定单一写入服务，或迁移到带事务和版本校验的 SQLite，并补充真正的多进程竞争测试。
2. **音频处理的并发上限（P1）。** 当前每个 chunk 都创建一个线程，`pending=min(1000, …)`
   只限制计数字段，并未限制工作数量；SenseVoice 解码锁也不等于入口限流。
   建议固定工作线程数和有界队列，队列满时提供可重试错误，并保证拒收不消耗音频序号。
3. **统一 Live 参数契约（P2）。** 本轮已把布尔校验收敛到 Store；下一步可将时长、时间戳、
   音频序号、事件结构等校验也集中定义，减少 HTTP、工具调用和原生入口各自转换参数的情况。
4. **逐步拆分大模块（P2）。** 优先从 `webapp.py` 提取 Live API 和业务服务，保持路由薄而明确；
   使用现有 HTTP 回归确保行为一致，再处理 Mission 与 CLI 的大模块。
5. **发布前运行验证。** 在 Windows/macOS 上完成 8–12 小时 Live/daemon 运行、睡眠唤醒、
   模型超时和磁盘异常的组合验证，记录真实的延迟、峰值线程数、临时音频占用和恢复时间。
