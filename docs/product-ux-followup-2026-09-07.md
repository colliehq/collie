# Collie：减少干预与 UI/UX 复验

这一轮接续 [首轮产品审计](project-audit-2026-09-06.md)，基线是 `1f5714f8`。用户明确选择：**跳过可选步骤，必要时才询问**，并授权继续使用 Claude Code 订阅进行真实实验和本地提交。日期采用 UTC；当地仍为 9 月 6 日晚。

## 产品判断

原版提示词已经能让模型在简单场景中省略可选内容，但工具返回“需要本人处理”时，执行层仍直接暂停整项任务。仅改提示词或把权限设成全部允许，都不能解决这个问题。

默认行为现在是：能自行决定的可撤销细节直接完成；受阻的可选路径记录省略原因；必要依赖没有安全替代方案时才请求用户处理。省略不会被记为已授权或已完成，也不会让已声明的必做范围消失。

当前最影响易用性的根因是执行层、持久状态和页面提示没有表达同一种任务状态。局部重构这些边界比全面替换架构更直接：既减少无谓暂停，也保留已完成成果、真实权限范围和结果未知时的恢复能力。现有原生循环默认不设固定轮数上限，本轮没有另加对话次数上限。

## 改动

| 原来的问题 | 现在的行为 |
|---|---|
| 可选来源要求 MFA、额外同意或缺少工具，整项任务直接停下 | `skip_optional` 和可选工具边界记录省略，继续主要工作 |
| 把“不阻塞当前分支”误当成“可以省略” | 必须明确可选；存在覆盖范围时只能匹配非必做分支 |
| 两个授权或等待条件交替出现，耗尽预算 | 检查请求之间是否有实际进展；无进展时停在明确依赖上或等待定时器 |
| 重复授权导致还有独立必做工作时也暂停 | 保留请求并继续独立范围；全部依赖同一条件时才整体暂停 |
| 用户处理了要求，继续后可能再次被问 | 准确请求 ID 对应一次持久回答；回答、需求账本和状态同事务提交，重试不会重复改范围 |
| 模型描述中的年龄文字被当成已确认个人事实 | 推测仅作参考；自动使用事实要求明确的 `profile_claim` 和精确声明 |
| 审阅模式提供无法兑现的持久授权按钮 | 不再提供该模式不会使用的作用范围 |
| 本地任务需要处理，但侧栏没有提示 | “需要你”包含本地必要阻塞和恢复任务，点击直达任务 |
| 已解决授权仍显示在任务卡片里 | 界面使用服务端过滤后的待处理列表 |
| 任务控制位于冗长日志末尾 | 控制放在进度旁边；详细步骤折叠，展开状态跨轮询保留 |
| 恢复要输入技术代号，再确认一次 | 使用未预选的结果选项和已检查声明；不会自动重放不确定操作 |
| 取消任务、取消子任务、保留或忽略学习建议有重复确认 | 按钮表达一次明确操作，保留任务审计历史 |
| 语言设置晚于任务页面返回，暂停任务一直夹杂英文 | 语言载入后更新动态内容，保留补充草稿和展开状态 |
| 设备页首先展示架构图，页面名称与导航不一致 | 先展示设备状态和当前分工，协作原理折叠；统一“设备与协作”名称 |
| 系统活动页只占不到一半窗口，导航和状态夹杂英文 | 使用可用页面高度，翻译主要页签、状态和空列表；补齐 Live 音频说明 |

实现见 [Mission](../harness/mission.py)、[可选步骤策略](../harness/mission_intervention.py)、[服务入口](../harness/missionweb.py)、[Web UI](../harness/webui/index.html)。开源架构对照见 [8 个固定版本的源码参考](agent-harness-reference-2026-09-06.md)。

## 真实模型实验

使用已登录的 Claude Code / Claude Agent SDK，实际模型为 `claude-opus-5`，未配置 API key 路由。日志中的 API 等价费用不代表订阅实际账单。

### 多轮可选阻塞

同样的目标：先检查可选来源，再用已有事实保存本地报告。模型真实运行，来源的 MFA、额外同意和不可用结果由本地测试能力提供；没有连接真实外部账号。

| 场景 | 原版 `1f5714f8` | 改进版 `b3c5b88c` |
|---|---|---|
| 可选来源需要本人 MFA | 1 次模型调用后等待用户；未保存报告 | 4 次调用，20.102 秒；报告通过独立文件检查 |
| 可选来源需要新同意 | 1 次模型调用后等待用户；未保存报告 | 4 次调用，21.177 秒；报告通过独立文件检查 |
| 可选来源不可用 | 1 次模型调用后等待用户；未保存报告 | 4 次调用，19.413 秒；报告通过独立文件检查 |

三个新版任务都只检查可选来源一次，保留省略原因，没有挂起授权请求。原版较短的耗时代表提前停止，不代表更快完成任务。

### 下一步决策与连续编码

12 个单步决策场景覆盖可选账号、MFA、购买、工具缺失、必要身份认证、必做范围、未知发送结果、中文要求和可撤销默认选择。**改进前后均为 12/12**；该组只检查下一步的方向，不能证明完整任务成功，也不能据此声称性能提升。

连续编码使用区间合并和递归配置合并两个标准库项目。每项分别走 Claude Code worker 和 Collie 原生路径，先实现，再追加兼容性要求，最后做只读追问。四组共 12 次请求全部完成，包括 8 次实现和 4 次只读追问；页面刷新和移动布局没有产生 JavaScript 错误。

| 项目 / 执行路径 | 首次实现 | 追加要求 | 工作区外独立验收：首次 / 追加 | 最终项目测试 |
|---|---:|---:|---:|---:|
| 区间合并 / Claude Code | 122.131 秒 | 80.052 秒 | 106 / 207 项通过 | 62 项通过 |
| 区间合并 / Collie | 95.251 秒 | 90.859 秒 | 106 / 207 项通过 | 36 项通过 |
| 配置合并 / Claude Code | 57.929 秒 | 89.353 秒 | 7 / 12 项通过 | 48 项通过 |
| 配置合并 / Collie | 72.233 秒 | 104.902 秒 | 7 / 12 项通过 | 39 项通过 |

区间任务包含生成器、随机样本、非法数值、输入不变性和可配置的相接区间合并；配置任务包含递归、深拷贝、列表替换和可选的空值删除。独立验收不依赖模型自行报告成功。Claude Code 两组的原生会话 ID 在各自三次请求间保持一致。

验证配置有一个明确限制：Run setup 的 Required 选择目前只在当前页面保留。首次实现均由 Collie 宿主运行 Required 检查；刷新后的追加请求回到 Auto，外部 Claude Code 的这两次运行没有宿主验证证据，收据也准确标为未验证。每次实现仍通过了工作区外独立验收，最后另外执行四个保存项目的完整测试，均通过。不能把这些外部验收倒算成当时已执行的 Required 检查。

这些小样本用于发现工作流问题，不是通用模型排行榜。

### Claude Code 源码复审

使用原生 Claude Code 做了三轮只读源码审阅，分别运行约 349、405、273 秒。首轮定位到执行层不合理暂停、重复依赖空转、事实推测、授权按钮和入口提示问题；第二轮检查新实现，发现“已处理”可能扩大到另一项要求、无关授权遮住通用继续入口、可选省略误删其他请求三处问题，均已修复并加入回归。

第三轮确认上述三处修复，并发现授权说明先截断再计算身份的边界问题。`cf0fb3a7` 改为先对完整说明计算摘要；过长的新要求请模型重新写清完整条件，再呈现给用户，不能批准只显示了一部分的要求。可选步骤身份也使用完整原文。“我已处理”只对应准确的要求，不创建通用授权。
