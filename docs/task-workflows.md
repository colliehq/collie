# 持续任务、补充要求与保存结果

## 选择入口

| 你想做什么 | 入口 |
|---|---|
| 提问、修改代码、继续当前项目 | New task 或终端交互会话 |
| 长期跟踪目标，允许等待、暂停和交接 | Tasks / Mission |
| 尝试多个实现，检查后选择结果 | Pack |
| 边工作边记录笔记、摘要与协作回顾 | Live Copilot |

先选择已经配置、登录的模型或 worker。Collie 原生循环可以使用所选模型和 Collie 工具；外部 Claude Code 使用自己的会话和受支持的工具配置。当前外部 Claude Code 适配器提供文件工具，不能任意执行 shell。需要项目命令时，可使用原生 Collie，或配置由 Collie 宿主执行的 Required 检查。

## 当前任务还没结束时输入下一条

默认少打扰：可选步骤缺少权限或工具时，Collie 会省略并记录原因，继续主要工作。必做步骤受阻且没有安全替代方案时，会出现在“需要你”。任务中的“我已处理这项要求”只记录对应的准确要求；暂停任务仍保持暂停，不会把整项任务记为完成。

恢复面板会要求选择上次操作是否发生，并确认已经查看实际结果。不确定时先保留进度，避免重复操作。具体改动和实验证据见 [减少干预与 UI/UX 复验](product-ux-followup-2026-09-07.md)。

普通 Web 对话默认把追加输入作为下一项任务排队。看到 **Request saved** 才表示已持久保存；网络失败时保留草稿，可以重试。刷新后，已保存的请求仍在队列中，可以查看、编辑未开始的要求或移除它。

正常完成后，Collie 可以继续下一项。点击 **Stop** 后，未开始的要求仍保留，但不会自动启动；点击 **Send next** 才继续。不要把“已经保存”理解为“模型已经读到”。

默认排队模式下，任务运行时按 **Ctrl/Cmd + Shift + Enter**，可将这一次输入作为插话发送给支持该能力的 worker；使用 IDE 的默认插话偏好时，同一快捷键反向切换为排队。插话先进入保存队列，只有实际进入执行边界后才在当前回答中显示 **steering delivered**。图片和手工附加的编辑器上下文使用后续任务队列。

终端交互会话可以使用：

```text
/queue
/queue show <id>
/queue remove <id>
/next
```

`/next` 开始当前会话最早的待处理请求。恢复会话时使用它保存的项目目录；目录已经不存在时，先恢复该目录。

## 在 Mission 中途补充或纠正要求

从 **Tasks** 打开任务，使用 **Update this task → Save instruction**。这会保存新的需求，不会启动另一个执行者；暂停状态仍保持暂停。

草稿在当前浏览器标签页内跨刷新保留，保存成功后才清空。**Saved instructions** 中可以查看完整文本及状态：

- **Saved · awaiting next boundary**：已保存，等待当前执行者读取。
- **Read by Collie**：已进入任务的需求记录。它不表示已经实现，仍需看任务结果和检查。
- **Not applied**：未应用，旁边说明原因；按提示处理后以新要求提交。

后续要求按提交顺序补充或修改原目标。已通过的检查不能证明后来新增的要求；Collie 会使旧的完成证据失效，并按新范围继续。单条补充最多 20,000 个字符；超限会明确拒绝，不能靠截掉末尾假装保存成功。

已经结束的 Mission 保留原结果；进一步工作应开始新任务。处于结果未知的恢复边界时，先核对并处理恢复问题。**Read full coding report** 打开保存的完整代码报告；状态卡片只是摘要。

## 让代码检查成为完成条件

在 Run setup 中将 Verification 设为 **Required**，确认 Proposed verification command 是你要执行的项目检查，例如 `python -m unittest -q`。检查在当前修改之后由宿主执行，结果保存在本次运行记录中。

也可以从项目目录运行：

```shell
collie run "修复日期解析并保留现有行为" --runner collie --verification required --verify-command "python -m unittest -q"
```

Stop 会同时取消正在执行的受控检查。任务已取消或执行出错时，不会为了得到绿色标志再启动新检查。检查通过只证明该命令覆盖的范围。

## 查看和应用 Pack 保存的实现

在目标项目目录中运行这些命令：

```shell
collie pack "修复日期解析并保留现有行为" -n 2 --check "python -m unittest -q"
collie pack --saved
collie pack --saved <id>
collie pack --saved <id> --apply
```

第一条命令运行候选并保存选中结果，不立即应用。后面的查看和应用命令不会重新调用模型。Web 会话中也有 **Review saved changes** 和应用入口；刷新会话仍可找到保存结果。

应用前会比较当前文件与候选开始时的基线。如果你后来修改过同一文件，Collie 会报告冲突并保留两边内容。检查冲突后自行整合，或在恢复所需基线后重新应用；不要为了清掉提示直接丢弃自己的修改。不相关文件不受影响。

## 长任务为什么停止

普通原生循环默认没有固定轮数上限；设置中的 `MAX_TURNS=0` 表示不设轮数上限。显式设置的轮数、成本或 token 限制仍会生效。Mission 的明确时间和资源限制也仍然有效。

停止状态会区分正常结束、用户取消、预算或轮数耗尽、工具失败和需要核对的未知结果。遇到恢复提示，先看实际文件或外部系统发生了什么；不要把未知动作直接当作“没有执行”再来一次。受控进程树和工作目录约束不等于完整操作系统沙箱。
