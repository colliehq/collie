# Collie Task Evidence for Codex

This narrow local plugin provides `open_task`, `verify_task` and
`prepare_handoff`. Codex keeps editing through its own native tools. The
service does not start Codex, migrate native sessions, or control its other
tools. It uses the base `collie-harness` runtime without installing optional
model SDKs, browser automation, speech, desktop frameworks, or embeddings.

Before installing this folder through your Codex local plugin source:

Install the main repository's source or its single `collie_harness` wheel into
a new virtual environment. The [installation guide](INSTALL_LOCAL.md) covers
source archives, the whole-repository marketplace, and this folder on its own.
This folder contains no runtime copy; the unified wheel contains the service.

1. Install the runtime containing `harness.evidence_bridge` into a local
   Python environment. Use that environment's absolute Python executable as
   `.mcp.json`'s `command`.
2. Copy `config.example.json` to a user-owned absolute path outside the source
   workspaces. Replace its paths, goal, scope and check with your own approved
   values. Keep `state_dir` outside every registered workspace. Configuration
   is loaded at service startup; restart after changing it.
3. Replace `REPLACE_WITH_ABSOLUTE_USER_CONFIG_PATH` in `.mcp.json` with that
   file's absolute path. The supplied placeholder intentionally fails setup;
   it does not discover commands, choose a workspace, or create default state.
4. Install/enable the local-marketplace plugin and invoke `$task-handoff` in a native Codex
   conversation with registered workspace/check IDs, or a returned task ID.

To inspect the server directly, run:

```text
python -m harness.evidence_bridge --config /absolute/user/config.json
```

Its only transport is newline-delimited stdio JSON-RPC/MCP. A separate
`--state-dir /absolute/state` overrides the explicit configured state path.

The registered check runs project code under the local user's privileges via
Collie's existing process-tree verifier; it is not an OS sandbox. Only
configure commands you approve. Model tool arguments cannot change the command
or cwd. Scope fingerprints include configured files/directories, including
generated bytes; changed files yield stale evidence, unreadable/linked/bounded
snapshots yield unknown. Unknown check effects stay fenced across task IDs in
the same physical workspace. Receipt writes and boundary retirement share one
atomic journal commit. No automatic reconciliation/replay is provided.

The current service serializes requests. A check has its configured timeout;
queued MCP cancellation notifications do not stop it. Native host actions are
not locked by this evidence lease, so freshness is a point-in-time observation.
This plugin must be tested in native Codex, not a Collie runner configuration
that disables plugins/MCP. The implementation fixtures do not establish a
native Codex integration pass.
